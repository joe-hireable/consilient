## Stranger-runnable reproducibility package

The present forward-replay runner is not release-ready because repository, scratch and suite inputs
are hard-coded. [measured] Before release, expose them as explicit arguments and ensure the package:
[asserted]

1. runs from a clean checkout against a user-owned `--repo` and `--suite`, writing only to a caller-
   supplied `--output` or a newly created temporary directory;
2. gives the history miner the same caller-supplied output boundary; it currently writes row-level
   records beside its source, so release mode must default to aggregates and require an explicit
   outside-tree location before retaining rows;
3. records repository revision, platform, Python version, dependency lock, command, seed where
   applicable, suite identity, timeout and SHA-256 checksums;
4. emits the full contingency table, eligibility counts, parent/child classification, stopping-rule
   verdict and aggregate summary without copying source content;
5. includes public synthetic fixtures for clean, defect, drift and enhancement pairs, including a
   parent-and-child failure proving the control excludes a child-only false classification;
6. keeps raw local records outside the release archive by default and creates the public archive
   from an allowlist, never a denylist; and
7. is exercised by a stranger on Windows and Linux from the written instructions, with the produced
   checksums compared to `expected/`.

The target invocation is: [asserted]

```powershell
python reproduce/run.py --repo C:/path/to/public-repository --suite tests/unit --output C:/path/to/new-output
```
