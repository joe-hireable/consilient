- Mechanical: the existing watchdog bounds child-process execution and kills that process tree on timeout, but command construction and post-run Git work sit outside it; the new monotonic acceptance measurement bounds the whole `run_harness` call. [measured]
- Cognitive: mutating the principal's interactive Grok setup would make unattended dispatch alter attended behaviour, so the solution confines every override to the child process. [asserted]
- Epistemological: a fast sentinel proves useful completion for this client and prompt, not universal plugin absence, future latency, or provider availability. [measured]

## Synthesis and delta

- The mechanism captures the original auth path before replacing `GROK_HOME`, assigns a run-local state directory, passes that original path as `GROK_AUTH_PATH`, disables six source-recognised Claude compatibility surfaces in the child environment, and lets the requested permission policy be the sole source of native approval flags. [measured]
- The imported mechanism is least ambient authority from process isolation: give the child a fresh state root and the one pre-existing credential reference it needs, rather than inheriting or rewriting global state. [asserted]
- The metered-key refusal remains ahead of launch, the existing timeout remains the child-process failure boundary, and the live check separately measures the whole call. [measured]
- The killing check is `python -m pytest tests/test_grok_arm.py -q`: the full `run_harness` call must finish before 60 seconds with status `ok`, exit zero, and normalised stdout exactly equal to a transformed answer that is absent from the brief. [measured]
- The delta over the plain `GROK_HOME` answer is the explicit external auth path and the compatibility switches; removing only the switches restored a 60.76-second timeout in the live ablation. [measured]
